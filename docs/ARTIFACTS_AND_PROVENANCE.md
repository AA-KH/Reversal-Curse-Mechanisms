# Artifact and Provenance Guide

This guide describes how the public repository is organized as a scientific artifact. It complements `docs/REPRODUCTION_AUDIT.md`, which gives the GPT-2 Medium paper-specific mapping from claims to scripts and files.

## Canonical Scope

The official paper pipeline is the `gpt2_medium` model profile. The `gpt2_small` and `gpt2_large` profiles are first-class scale-replication paths and write to model-specific directories so they do not overwrite the paper artifacts.

The released lightweight artifacts are:

- `data/`: SynthRel-500 and fixed train/validation/test splits.
- `results/gpt2_medium/tables/`: behavioral evaluations, statistical summaries, and derived manuscript tables for GPT-2 Medium.
- `results/gpt2_medium/processed/`: processed mechanistic outputs for GPT-2 Medium.
- `paper/figures/gpt2_medium/`: GPT-2 Medium manuscript figures generated from saved outputs.
- `results/gpt2_small/`, `paper/figures/gpt2_small/`, `results/gpt2_large/`, and `paper/figures/gpt2_large/`: GPT-2 scale-replication artifacts.
- `reports/gpt2_medium/`: generated manifest and replication status report.

The local heavyweight artifacts are intentionally not part of the public source tree:

- `experiments/`: training checkpoints and local run directories.
- `wandb/`: offline Weights & Biases logs.
- `logs/`: local execution notes.
- `scratch/`: exploratory or one-off development scripts.
- `.venv/`: local Python environment.

These paths are ignored by Git. They can be regenerated by the documented pipeline, but they should not be required for inspecting the saved CSV, JSON, and figure artifacts.

## Reviewer Checks

Run these from the repository root after installing dependencies:

```bash
make validate
make validate-outputs
make dry-run
make stats
make tables
make manifest
make report
```

The `dry-run` target prints the full end-to-end command sequence without launching expensive model training or mechanistic sweeps. The `validate-outputs` target confirms that the saved artifacts referenced by the manifest are present.

## Determinism Notes

- Dataset generation uses seed `42` and an in-repository fixed rejection set for synthetic entity names. It does not depend on host dictionaries or external word lists.
- `data/CHECKSUMS.sha256` records the released SynthRel-500 hashes.
- ICL evaluation uses fixed seed `42` by default and relation-matched demonstrations.
- Behavioral confidence intervals use 10,000 bootstrap resamples with seed `42`.
- Heavy model training can still vary slightly across hardware and low-level libraries. The saved outputs in `results/` are the lightweight verification artifacts for the reported paper results.

## Manifest

`src/pipeline_manifest.py` is the machine-readable paper-to-pipeline map. It generates:

- `reports/gpt2_medium/pipeline_manifest.json`
- `reports/gpt2_small/pipeline_manifest.json` for the Small scale profile
- `reports/gpt2_large/pipeline_manifest.json` for the optional scale profile

The generated manifest uses repository-relative paths so it is portable across machines.
